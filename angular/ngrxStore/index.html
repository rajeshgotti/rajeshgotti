    NGXS Store - Step by Step (Telugu)

    1. Store అంటే ఏమిటి?

    Store అంటే ఒక Central Data Box (Global Memory).

Application లో ఎక్కడైనా, ఏ Component నుండైనా
Data ని Save, Read, Update చేయవచ్చు.

Falcon Project లో Store కోసం NGXS Library ఉపయోగిస్తారు.

Data SessionStorage లో Persist అవుతుంది.
(Page Refresh అయినా Data పోదు.)

Example:

- patientId
- visitId
- gender
- patientModel

ని Store చేస్తుంది.

    7. Action Handler

    @Action(storePatientIdVisitIdAction)
storePatientIdVisitIdAction(
  { getState, patchState }: StateContext<storePatientIdVisitIdModel>,
  { payload }: storePatientIdVisitIdAction
) {

  const state = getState();

  const { patientModel } = payload || {};

  if (patientModel) {
    patientModel.patientType =
      patientModel.patientType ??
      patientModel.patientVisitType;
  }

  patchState({
    patientId: payload.patientId,
    visitId: payload.visitId,
    gender: payload.gender,
    patientModel: patientModel
  });

}

    NGXS Store - Complete Flow

    NGXS Store lo data flow Action → State → Store → Selector → Component order lo untundi.

    patient.actions.ts

    export class AddPatient {
  static readonly type = '[Patient] Add Patient';

  constructor(
    public payload: {
      prefix: string;
      fname: string;
      lname: string;
    }
  ) {}
}

export class ClearPatient {
  static readonly type = '[Patient] Clear Patient';
}

    Explanation

    Action anedi oka message/command.

    Component nundi dispatch() chesina data first ikkadiki vastundi.

    Payload lo unna values State ki forward avutayi.

    patient.state.ts

    import { Injectable } from '@angular/core';
import { Action, Selector, State, StateContext } from '@ngxs/store';
import { AddPatient, ClearPatient } from './patient.actions';

export interface PatientStateModel {
  prefix: string;
  fname: string;
  lname: string;
}

@State<PatientStateModel>({
  name: 'patient',
  defaults: {
    prefix: '',
    fname: '',
    lname: ''
  }
})

@Injectable()

export class PatientState {

  @Selector()
  static getPatient(state: PatientStateModel) {
    return state;
  }

  @Action(AddPatient)
  addPatient(ctx: StateContext<PatientStateModel>, action: AddPatient) {

    ctx.setState({
      prefix: action.payload.prefix,
      fname: action.payload.fname,
      lname: action.payload.lname
    });

  }

  @Action(ClearPatient)
  clearPatient(ctx: StateContext<PatientStateModel>) {

    ctx.setState({
      prefix: '',
      fname: '',
      lname: ''
    });

  }

}

    Explanation

    State anedi Store lo data save ayye place.

    defaults application start ayinappudu initial values assign chestundi.

    setState() Store lo values update chestundi.

    @Selector() Store nundi data read cheyyadaniki use avutundi.

    NGXS Action Type & State Name - Telugu Explanation

    Action Type అంటే ఏమిటి?

    export class ReportAction {

  static readonly type = '[SetReport] Set Report';

}

    static readonly type అనేది Action Identifier (Unique Name).

    మనం code లో direct గా ఈ string ని use చేయము.

    కానీ NGXS internally ఈ string ని use చేసి ఏ Action run చేయాలో decide చేస్తుంది.

    Why do we need Action Type?

    1. Unique Identifier

    Component లో

    this.store.dispatch(
  new ReportAction({
    prefix: 'Mr',
    fname: 'Rajesh'
  })
);

    dispatch చేసినప్పుడు,

    NGXS ReportAction.type

    '[SetReport] Set Report'

    అనే string ని internally check చేసి,

    ఈ Action కి సంబంధించిన handler ని execute చేస్తుంది.

    @Action(ReportAction)

addReport(ctx, action) {

}

    మనకి class name కనిపిస్తుంది.

    కానీ NGXS internally type string తోనే match చేస్తుంది.

    2. Redux DevTools

    Redux DevTools install చేసి ఉంటే,

    Dispatch అయిన ప్రతి Action ఈ name తో కనిపిస్తుంది.

    Example

    [SetReport] Set Report

Payload

{
  prefix: "Mr",
  fname: "Rajesh"
}

    Debugging కి చాలా useful.

    3. Best Practice

    Format usually ఇలా ఉంటుంది.

    [Feature] Action Name

    Example

    '[Report] Set Report'

'[Report] Clear Report'

    దీనివల్ల Redux DevTools లో

    అన్ని Report actions ఒకే group లో కనిపిస్తాయి.

    Can I write like this?

    export class ReportAction {

  static readonly type =
  '[SetReport] Set Report';

}

export class ClearReport {

  static readonly type =
  '[ClearReport] Clear Report';

}

    ✅ Yes.

    Perfectly valid.

    NGXS కి important విషయం

    Action Type unique గా ఉండాలి.

    String ఏదైనా పెట్టొచ్చు.

    Duplicate మాత్రం ఉండకూడదు.

    What is name in State?

    @State<ReportModel>({

  defaults: {
    prefix: '',
    fname: ''
  }
})

    name అనేది Store లో ఈ State కి ఇచ్చే unique key (address).

  },

    fname: ""

  }

}

    అనేదే Store key.

    Selector automatic గా

    Can I change the name?

    Yes.

    Better naming:

    @State<ReportModel>({
  name: 'report',
  defaults: {
    prefix: '',
    fname: ''
  }
})

    {

  patient: { },

  report: {

    fname: ""

  }

    ఇది clean & readable.

    Important Rules

    ✅ Every Action type should be unique.

    ✅ Every State name should be unique.

    ❌ Two Actions should not have the same type.

    ❌ Two States should not have the same name.

  name: 'PatientState',

  },
})

@Injectable()
export class PatientStateClass {

  @Selector()
  static getPatientName(
    state: PatientStateModel
  ): string | null {
    return state.patientName;
  }

  @Action(SetPatientName)
  setPatientName(
    ctx: StateContext<PatientStateModel>,
    action: SetPatientName
  ) {
    ctx.patchState({
      patientName: action.payload
    });
  }

  @Action(ClearPatientName)
  clearPatientName(
    ctx: StateContext<PatientStateModel>
  ) {
    ctx.patchState({
      patientName: null
    });
  }

}

  storePatientIdVisitIdAction(

    });

    { patchState }: StateContext<storePatientIdVisitIdModel>
  ) {
    patchState({
      patientId: 0,
      visitId: 0,
      gender: '',
      patientModel: null,
    });
  }

2. take – Limit to First N Values
The take operator emits only the first N values, then completes.
import { interval } from 'rxjs';
import { take } from 'rxjs/operators';

interval(1000).pipe(
  take(3)
).subscribe(console.log); //output: 0 1 2

-------First-----
3. first – Emit Only the First Value (Optionally Matching a Condition)
The first operator emits only the first value from the stream and completes.

import { of } from 'rxjs';
import { first } from 'rxjs/operators';

of(1, 3, 7, 9).pipe(
  first(x => x > 5)
).subscribe(console.log);// Output: 7
---------Last-------
4. last – Emit Only the Last Value (Optionally Matching a Condition)
The last operator waits for the stream to complete and emits the last value (optionally matching a predicate).

import { of } from 'rxjs';
import { last } from 'rxjs/operators';

of(1, 4, 6, 9).pipe(
  last(x => x % 2 === 0)
).subscribe(console.log); // Output: 6

-----------skip------

5. skip – Ignore First N Values
The skip operator skips the first N emitted values, then emits the rest.

import { of } from 'rxjs';
import { skip } from 'rxjs/operators';

of(10, 20, 30, 40).pipe(
  skip(2)
).subscribe(console.log); //30  40
    Angular Interview Question- State Management (2+ Years)

    What is State Management?

    Interview Answer

    State Management is a technique used to store and manage shared application data in a centralized Store. Instead of passing data between multiple components using @Input() and @Output(), we keep the data in one central location. Any component can access or update the data from the Store.

    It helps make the application more maintainable, scalable, and easier to debug.

    Why do we need State Management?

    Interview Answer

    In large Angular applications, many components require the same data.

    Without State Management:

    • We have to pass data through multiple parent-child components.
    • We need many shared services.
    • Keeping data synchronized becomes difficult.

    With State Management:

    • There is a Single Source of Truth.
    • Any component can access the latest data.
    • Data remains consistent across the application.
    • Large applications become easier to maintain.

    Which State Management library have you used?

    Interview Answer

    I have worked with NGXS.

    In NGXS, we define:

    • Actions
    • State
    • Selectors

    We dispatch an Action to update the Store, and components read the updated data using Selectors.

    Explain NGXS Flow

    Component
      │
      ▼
dispatch(Action)
      │
      ▼
    Action
      │
      ▼
    State
      │
      ▼
setState()/patchState()
      │
      ▼
     Store
      │
      ▼
   Selector
      │
      ▼
  Component

    Explanation

    • Component dispatches an Action.
    • State receives the Action.
    • State updates the Store using setState() or patchState().
    • Components read the updated data using select() or selectSnapshot().

    What is the Store?

    Interview Answer

    The Store is the centralized memory where the application's shared data is stored.

    Instead of storing shared data inside individual components, we store it in the Store so it can be accessed from anywhere in the application.

    What are the main parts of NGXS?

    Part Purpose
    Action Describes what needs to happen (Add, Update, Delete, Clear)
    State Stores and manages the application data
    Store Central place where all application state is stored
    Selector Reads data from the Store
    Dispatch Sends an Action to update the State

    Real-Time Example

    Suppose your application contains:

    • Demographics Component
    • Orders Component
    • Billing Component
    • Summary Component

    When a user selects a patient from the Demographics page:

    Demographics Component
         │
         ▼
dispatch(AddPatient)
         │
         ▼
      NGXS Store
    /      |      \
   ▼       ▼       ▼
Orders   Billing  Summary

    All components receive the same patient information directly from the Store.

    There is no need to pass data using @Input() and @Output() through multiple components.

    Benefits of State Management

    • Centralized data management
    • Single Source of Truth
    • Reduces @Input() and @Output() usage
    • Easy data sharing between components
    • Better code organization
    • Easier debugging
    • Predictable data flow
    • Easy to maintain large applications

    30-Second Interview Answer

    State Management is a technique used to manage shared application data in a centralized Store. I have worked with NGXS, where we dispatch Actions to update the State and use Selectors to read the data. This provides a Single Source of Truth, avoids passing data through multiple components using @Input() and @Output(), and makes the application easier to maintain, debug, and scale.
