    Flow structure how it travel from angular to dotnet to sql

    Office Project — Angular Form to SQL Server Complete Flow

    1. Overall Flow

    మన Office project లో Angular form లో user data enter చేసినప్పుడు data exactly ఏ order లో travel అవుతుందో చూద్దాం.

    Angular Form
     ↓
Angular Component
     ↓
Angular Service
     ↓
HTTP POST Request
     ↓
ASP.NET Core Web API
     ↓
Middleware Pipeline
     ↓
Controller
     ↓
DbContext
     ↓
EF Core
     ↓
Stored Procedure
     ↓
SQL Server
     ↓
Employee Table

    2. Angular Form

    ముందుగా user Angular form లో data enter చేస్తాడు.

    Example:

    First Name : Raj
Last Name  : Kumar
Gender     : Male

    User Save button click చేస్తాడు:

    <button (click)="empSave()">Save</button>

    అప్పుడు:

    Angular Form
     ↓
empSave()

    3. Angular Component

    empSave() method లో form data తీసుకొని object తయారు చేస్తాం.

    empSave() {
    let empObj = new EmpModels();

    empObj.empId = this.empId ?? 0;
    empObj.empFName = this.empForm.get('empFName')?.value;
    empObj.empLName = this.empForm.get('empLName')?.value;
    empObj.gender = this.empForm.get('gender')?.value;

    this.ser.postEmps(empObj).subscribe(...);
}

    Object ఇలా తయారవుతుంది:

    {
    "empId": 0,
    "empFName": "Raj",
    "empLName": "Kumar",
    "gender": "Male"
}

    4. Angular Service

    Component direct గా backend కి వెళ్లదు.

    Component:

    this.ser.postEmps(empObj);

    అని Angular Service ని call చేస్తుంది.

    Service లో:

    postEmps(body) {
    return this.http.post(
        environment.baseurl2 + environment.getEmp,
        body
    );
}

    ఇప్పుడు HTTP request తయారవుతుంది:

    POST
https://localhost:7205/api/Employee

    Body:

    {
    "empId": 0,
    "empFName": "Raj",
    "empLName": "Kumar",
    "gender": "Male"
}

    5. Angular నుంచి .NET కి Request

    ఇక్కడ ఒక important point:

    Request మొదట Program.cs లోని Controller code కి directly వెళ్లదు.

    Request ASP.NET Core application లోకి వచ్చినప్పుడు Middleware Pipeline ద్వారా travel అవుతుంది.

    Angular
     ↓
HTTP Request
     ↓
ASP.NET Core
     ↓
Middleware Pipeline
     ↓
Controller

    6. Program.cs

    Program.cs లో application configuration మరియు middleware pipeline configure చేస్తాం.

    Example:

    var app = builder.Build();

app.UseHttpsRedirection();

app.UseAuthorization();

app.MapControllers();

app.Run();

    Program.cs లో POST business logic execute చేయము.

    MapControllers() వల్ల request సరైన Controller endpoint కి route అవుతుంది.

    POST /api/Employee
       ↓
MapControllers()
       ↓
EmployeeController

    7. EmployeeController

    Controller లో:

    [HttpPost]
public IActionResult CreateEmployee(EmployeeModel employee)
{
    string str = _context.CreateEmployee(employee);

    return Ok(new JsonResult(str));
}

    Angular పంపిన JSON:

    {
    "empId": 0,
    "empFName": "Raj",
    "empLName": "Kumar",
    "gender": "Male"
}

    ASP.NET Core model binding ద్వారా JSON data:

    JSON
   ↓
EmployeeModel employee

    గా convert అవుతుంది.

    8. Controller → DbContext

    Controller లో:

    _context.CreateEmployee(employee);

    అని call చేస్తున్నాం.

    Flow:

    EmployeeController
       ↓
OfficeDbContext

    9. DbContext → Stored Procedure

    OfficeDbContext లో:

    public string CreateEmployee(EmployeeModel employee)
{
    var result = this.Database.ExecuteSqlRaw(
        "EXEC InsertEmployee @EmpId={0}, @EmpFName={1}, @EmpLName={2}, @Gender={3}",
        employee.EmpId,
        employee.EmpFName,
        employee.EmpLName,
        employee.Gender
    );

    return result.ToString();
}

    ఇక్కడ EF Core SQL Server కి command పంపుతుంది.

    OfficeDbContext
      ↓
ExecuteSqlRaw()
      ↓
InsertEmployee Stored Procedure

    10. Stored Procedure

    మన InsertEmployee Stored Procedure లో:

    IF (@EmpId = 0)
BEGIN
    -- INSERT
END
ELSE
BEGIN
    -- UPDATE
END

    Angular నుంచి:

    {
    "empId": 0
}

    వచ్చింది.

    కాబట్టి:

    EmpId = 0
     ↓
  INSERT

    అవుతుంది.

    11. SQL Server

    Stored Procedure చివరకు INSERT operation execute చేస్తుంది.

    INSERT INTO Employee

    @NewEmpId,

    అప్పుడు data Employee table లో save అవుతుంది.

    EmpId | EmpFName | EmpLName | Gender
--------------------------------------
  1   |   Raj    |  Kumar   | Male

    13. Important — Program.cs ఎక్కడ వస్తుంది?

    Main point:

    Angular
     ↓
HTTP Request
     ↓
ASP.NET Core
     ↓
Middleware Pipeline
     ↓
Controller

    Program.cs ప్రతి request కి వెళ్లి Controller method ని manually call చేయదు.

    Application start అయినప్పుడు Program.cs:

    Services configure చేస్తుంది
         +
Middleware configure చేస్తుంది
         +
Controllers map చేస్తుంది

    అందుకే simple గా:

    Program.cs
     ↓
Application Setup / Pipeline

Controller
     ↓
API Request Handling

DbContext
     ↓
Database Communication

Stored Procedure
     ↓
SQL / Database Operation

SQL Server
     ↓
Actual Data Storage

     ↓

    15. Easy Way to Remember

    Angular Form
     ↓
Component
     ↓
Service
     ↓
HTTP
     ↓
Middleware
     ↓
Controller
     ↓
DbContext / EF Core
     ↓
Stored Procedure
     ↓
SQL Server
     ↓
Table

    One-line concept:

    User Angular form లో data enter చేస్తాడు → Component object తయారు చేస్తుంది → Service HTTP request పంపుతుంది → ASP.NET Core Middleware request ని process చేస్తుంది → Controller receives it → DbContext EF Core ద్వారా Stored Procedure call చేస్తుంది → SQL Server table లో data save/update అవుతుంది.

    Creating SP by KannaBabu

    SSMS — Employee Stored Procedures

    Syntax:

    CREATE PROCEDURE procedureName(parameters)

  AS BEGIN
    SQL STATEMENTS

  END; 

***Syntax to call/invoke ***
EXEC procedureName

    1. Create Employee Table

    CREATE TABLE emp (
    eno INT,
    ename  VARCHAR(50),
    salary MONEY
);

    2. Create Procedure to Add Employee

    CREATE PROCEDURE proc_addemp
    @eno INT,
    @ename VARCHAR(50),
    @sal MONEY
AS
BEGIN
    INSERT INTO emp
    VALUES
    (
        @eno,
        @ename,
        @sal
    );
END;

    To Execute:

    EXEC proc_addemp;

    To Insert Values:

    EXEC proc_addemp 101, 'Anil', 2000;

    3. Create Procedure to Update Employee Details

    Q) Create a procedure to update employee details based on eno?

    CREATE PROCEDURE proc_updateemp
    @eno INT,
    @ename VARCHAR(50),
    @sal MONEY
AS
BEGIN
    UPDATE emp
    SET
        ename = @ename,
        salary = @sal
    WHERE eno = @eno;
END;

    To Execute:

    EXEC proc_updateemp;

    To Update Values:

    EXEC proc_updateemp 101, 'anilkumar', 30000;

    4. Create Procedure to Display Employee Details

    Q) Create a procedure to display employee details?

    CREATE PROCEDURE proc_getemp
AS
BEGIN
    SELECT *
    FROM emp;
END;

    To Execute:

    EXEC proc_getemp;

    5. Create Procedure to Delete Employee Details

    Q) Create a procedure to delete employee details based on employee number?

    CREATE PROCEDURE proc_deleteemp
    @eno INT
AS
BEGIN
    DELETE FROM emp
    WHERE eno = @eno;
END;

    To Execute:

    EXEC proc_deleteemp;

    To Delete Based on Employee ID:

    EXEC proc_deleteemp 101;

    6. Complete Stored Procedure Flow

    emp Table
   ↓
┌──────────────────────────────┐
│ proc_addemp                  │ → INSERT
│ proc_updateemp               │ → UPDATE
│ proc_getemp                  │ → SELECT
│ proc_deleteemp               │ → DELETE
└──────────────────────────────┘

    DTO'S

    DTO — Data Transfer Object

    1. What is DTO?

    DTO = Data Transfer Object

    DTO అంటే:

    ఒక layer నుంచి ఇంకొక layer కి లేదా Client ↔ API మధ్య అవసరమైన data మాత్రమే transfer చేయడానికి ఉపయోగించే object.

    Your project flow:

    Angular / Swagger
       ↓
Controller
       ↓
DTO
       ↓
Service
       ↓
Repository
       ↓
DbContext
       ↓
Database

    2. Why Do We Need DTO?

    Initially, you may use the database model directly in the Controller:

    [HttpPost]
public IActionResult PostMobile(MobileModels mobile)
{
    // ...
}

    Here MobileModels represents the database table:

    public class MobileModels
{
    public int MobileId { get; set; }

    public string MobileName { get; set; }

    public string MobileModel { get; set; }

    public decimal Price { get; set; }
}

    Suppose MobileId is generated by SQL Server:

    MobileId INT IDENTITY(1,1)

    SQL Server automatically generates the MobileId.

    Therefore, the client does not need to send MobileId when creating a new mobile.

    Instead of sending:

    {
    "mobileId": 0,
    "mobileName": "Apple",
    "mobileModel": "iPhone 16",
    "price": 80000
}

    We can create a Request DTO:

    public class MobileRequestDto
{
    public string MobileName { get; set; }

    public string MobileModel { get; set; }

    public decimal Price { get; set; }
}

    Now Angular only needs to send:

    {
    "mobileName": "Apple",
    "mobileModel": "iPhone 16",
    "price": 80000
}

    3. Main Uses of DTO

    3.1 Send Only Required Data

    Database Model may contain:

    MobileId
MobileName
MobileModel
Price
CreatedDate
UpdatedDate
InternalCode

    But the API request may need only:

    MobileName
MobileModel
Price

    Therefore:

    MobileRequestDto
      ↓
MobileName
MobileModel
Price

    3.2 Control Data Exposure

    Suppose the database model contains sensitive or internal fields:

    public class Patient
{
    public int PatientId { get; set; }

    public string PatientName { get; set; }

    public string PhoneNumber { get; set; }

    public string Password { get; set; }

    public string InternalCode { get; set; }
}

    We should not expose fields such as Password or InternalCode in the API response.

    Therefore, create a Response DTO:

    public class PatientResponseDto
{
    public int PatientId { get; set; }

    public string PatientName { get; set; }

    public string PhoneNumber { get; set; }
}

    Now the API controls which fields are returned to the client.

    3.3 Separate Database Structure from API Structure

    Database structure:

    Database
    ↓
Entity / Model
    ↓
DTO
    ↓
API

    Suppose the database later adds:

    CreatedDate
ModifiedDate
InternalCode

    If those fields are not required by the API, they do not need to be added to the DTO.

    Therefore, DTO provides a separation between the database model and the API contract.

    4. Request DTO vs Response DTO

    This is important.

    Request DTO

    Used for:

    Client → API

    Example:

    public class MobileRequestDto
{
    public string MobileName { get; set; }

    public string MobileModel { get; set; }

    public decimal Price { get; set; }
}

    Example request:

    {
    "mobileName": "Apple",
    "mobileModel": "iPhone 16",
    "price": 80000
}

    Response DTO

    Used for:

    API → Client

    Example:

    public class MobileResponseDto
{
    public int MobileId { get; set; }

    public string MobileName { get; set; }

    public string MobileModel { get; set; }

    public decimal Price { get; set; }
}

    Example response:

    {
    "mobileId": 1,
    "mobileName": "Apple",
    "mobileModel": "iPhone 16",
    "price": 80000
}

    Therefore:

    DTOs
  │
  ├── MobileRequestDto
  │
  └── MobileResponseDto

    5. DTO Validation

    DTOs can also contain validation attributes.

    using System.ComponentModel.DataAnnotations;

public class MobileRequestDto
{
    [Required(ErrorMessage = "Mobile name is required")]
    public string MobileName { get; set; }

    [Required(ErrorMessage = "Mobile model is required")]
    public string MobileModel { get; set; }

    [Range(1, 10000000, ErrorMessage = "Price must be greater than 0")]
    public decimal Price { get; set; }
}

    If the Controller has:

    [ApiController]

    ASP.NET Core automatically performs model validation.

    Therefore, manual validation such as:

    if (!ModelState.IsValid)
{
    return BadRequest(ModelState);
}

    is normally not required.

    using Mobile.DTOs;
using Mobile.Models;
using Mobile.Repositories;

namespace Mobile.Services
{
    public class MobileService : IMobileService
    {
        private readonly IMobileRepository _repository;

        public MobileService(IMobileRepository repository)
        {
            _repository = repository;
        }

        public List<MobileResponseDto> GetAllMobiles()
        {
            var mobiles = _repository.GetAllMobiles();

            return mobiles.Select(x => new MobileResponseDto
            {
                MobileId = x.MobileId,
                MobileName = x.MobileName,
                MobileModel = x.MobileModel,
                Price = x.Price
            }).ToList();
        }

        public string AddMobile(MobileRequestDto mobile)
        {
            var model = new MobileModels
            {
                MobileName = mobile.MobileName,
                MobileModel = mobile.MobileModel,
                Price = mobile.Price
            };

            return _repository.AddMobile(model);
        }

        public string DeleteMobile(int mobileId)
        {
            return _repository.DeleteMobile(mobileId);
        }
    }
}

    9. Step 7 — Repository

    Repository works with the database model.

    Therefore, DTOs are not required in the Repository.

    using Microsoft.EntityFrameworkCore;
using Mobile.Data;
using Mobile.Models;

namespace Mobile.Repositories
{
    public class MobileRepository : IMobileRepository
    {
        private readonly MobileDbContext _context;

        public MobileRepository(MobileDbContext context)
        {
            _context = context;
        }

        public List<MobileModels> GetAllMobiles()
        {
            return _context.Mobiles.ToList();
        }

        public string AddMobile(MobileModels mobile)
        {
            var result = _context.Database.ExecuteSqlRaw(
                "EXEC sp_AddMobile @MobileId={0},@MobileName={1},@MobileModel={2},@Price={3}",
                mobile.MobileId,
                mobile.MobileName,
                mobile.MobileModel,
                mobile.Price
            );

            return result.ToString();
        }

        public string DeleteMobile(int mobileId)
        {
            var result = _context.Database.ExecuteSqlRaw(
                "EXEC sp_DeleteMobile @MobileId={0}",
                mobileId
            );

            return result.ToString();
        }
    }
}
