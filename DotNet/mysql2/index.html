    JOINS — Complete Real-Time EMR Explanation

    🤔 Joins ఎందుకు అవసరం?

    Real scenario: మీరు Patient register చేసారు. But patient data ఒక్క table లో ఉండదు — multiple tables లో spread అవుతుంది:

    Patients table       → Name, DOB, Gender
States table         → State info
Cities table         → City info
Insurances table     → Insurance details
Visits table         → Hospital visits
Doctors table        → Assigned doctor

    Problem: Patient details చూపించాలంటే ఒక్క query లో అన్ని tables నుండి data కావాలి.

    Solution: JOINS — multiple tables ని ఒక result లో combine చేయడం.

    📊 EMR Real Example — Patient Registration

    మీ Patients table ఇలా ఉందని అనుకుందాం:

    Patients
┌───────────┬──────────────┬──────────┬────────┬─────────┬─────────────┐
│ PatientId │ PatientFName │ LastName │ DOB    │ StateId │ InsuranceId │
├───────────┼──────────────┼──────────┼────────┼─────────┼─────────────┤
│ 1         │ Rajesh       │ Reddy    │ 1995   │ 1       │ 10          │
│ 2         │ Priya        │ Sharma   │ 1998   │ 2       │ NULL        │
│ 3         │ Suresh       │ Kumar    │ 1990   │ 1       │ 11          │
└───────────┴──────────────┴──────────┴────────┴─────────┴─────────────┘

    States

    ┌─────────┬───────────────┐
│ StateId │ StateName     │
├─────────┼───────────────┤
│ 1       │ Telangana     │
│ 2       │ AndhraPradesh │
│ 3       │ Karnataka     │
└─────────┴───────────────┘

    Insurances

    ┌─────────────┬──────────────┬────────┐
│ InsuranceId │ CompanyName  │ Policy │
├─────────────┼──────────────┼────────┤
│ 10          │ Star Health  │ P001   │
│ 11          │ HDFC Ergo    │ P002   │
└─────────────┴──────────────┴────────┘

    Question:

    Angular UI లో patient list show చేయాలి — with State name and Insurance company, not IDs.

    Without JOIN → 3 separate queries.

    With JOIN → one query! ✅

    🔗 4 Types of JOINS

    1️⃣ INNER JOIN — Both tables లో ఉన్న data మాత్రమే

    SELECT
    p.PatientId,
    p.PatientFName,
    p.LastName,
    s.StateName
FROM Patients p
INNER JOIN States s
    ON p.StateId = s.StateId;

    Result:

    ┌───────────┬──────────────┬──────────┬───────────────┐
│ PatientId │ PatientFName │ LastName │ StateName     │
├───────────┼──────────────┼──────────┼───────────────┤
│ 1         │ Rajesh       │ Reddy    │ Telangana     │
│ 2         │ Priya        │ Sharma   │ AndhraPradesh │
│ 3         │ Suresh       │ Kumar    │ Telangana     │
└───────────┴──────────────┴──────────┴───────────────┘

    💡 Use case: Patient list where state mandatory during registration.

    2️⃣ LEFT JOIN — Left table అన్నీ + matching right table data

    SELECT
    p.PatientId,
    p.PatientFName,
    p.LastName,
    s.StateName,
    i.CompanyName AS Insurance,
    i.Policy
FROM Patients p
INNER JOIN States s
    ON p.StateId = s.StateId
LEFT JOIN Insurances i
    ON p.InsuranceId = i.InsuranceId;

    Result:

    ┌───────────┬──────────────┬──────────┬───────────────┬─────────────┬────────┐
│ PatientId │ PatientFName │ LastName │ StateName     │ Insurance   │ Policy │
├───────────┼──────────────┼──────────┼───────────────┼─────────────┼────────┤
│ 1         │ Rajesh       │ Reddy    │ Telangana     │ Star Health │ P001   │
│ 2         │ Priya        │ Sharma   │ AndhraPradesh │ NULL        │ NULL   │
│ 3         │ Suresh       │ Kumar    │ Telangana     │ HDFC Ergo   │ P002   │
└───────────┴──────────────┴──────────┴───────────────┴─────────────┴────────┘

    💡 EMR use case: Priya insurance take చేయలేదు — but ఆమెని miss చేయకూడదు.

    LEFT JOIN వాడితే NULL వస్తుంది but patient list లో ఉంటుంది.

    ⚠️ INNER JOIN వాడితే — Priya list లో miss అవుతుంది!

    3️⃣ RIGHT JOIN — Right table అన్నీ + matching left

    SELECT
    s.StateName,
    COUNT(p.PatientId) AS PatientCount
FROM Patients p
RIGHT JOIN States s
    ON p.StateId = s.StateId
GROUP BY s.StateName;

    Result:

    ┌───────────────┬──────────────┐
│ StateName     │ PatientCount │
├───────────────┼──────────────┤
│ Telangana     │ 2            │
│ AndhraPradesh │ 1            │
│ Karnataka     │ 0            │
└───────────────┴──────────────┘

    💡 Use case: Dashboard reports — "which states have no registered patients?"

    Note: RIGHT JOIN rarely వాడతారు. Same result LEFT JOIN తో achieve చేయొచ్చు — just swap table order.

    4️⃣ FULL OUTER JOIN — Both tables అన్నీ

    SELECT
    p.PatientFName,
    s.StateName
FROM Patients p
FULL OUTER JOIN States s
    ON p.StateId = s.StateId;

    💡 EMR లో rarely use — mostly data reconciliation reports కి use అవుతుంది.

    🏥 Real EMR Query — Complete Patient Details

    Scenario: Patient details page open చేసినప్పుడు — ఒక్క query లో అన్నీ కావాలి:

    Personal info
State
Insurance
Last visit date
Assigned doctor

    CREATE PROCEDURE sp_GetPatientFullDetails
    @PatientId INT
AS
BEGIN
    SET NOCOUNT ON;

    SELECT 
        p.PatientId,
        p.PatientFName + ' ' +
        ISNULL(p.MiddleName, '') + ' ' +
        p.LastName AS FullName,
        p.DOB,
        DATEDIFF(YEAR, p.DOB, GETDATE()) AS Age,
        s.StateName,
        ISNULL(i.CompanyName, 'No Insurance') AS InsuranceCompany,
        ISNULL(i.Policy, '-') AS PolicyNumber,
        v.LastVisitDate,
        d.DoctorName,
        d.Specialization
    FROM Patients p
    INNER JOIN States s 
        ON p.StateId = s.StateId
    LEFT JOIN Insurances i 
        ON p.InsuranceId = i.InsuranceId
    LEFT JOIN (
        SELECT PatientId, MAX(VisitDate) AS LastVisitDate
        FROM Visits
        GROUP BY PatientId
    ) v
        ON p.PatientId = v.PatientId
    LEFT JOIN PatientDoctorMapping pdm 
        ON p.PatientId = pdm.PatientId
    LEFT JOIN Doctors d 
        ON pdm.DoctorId = d.DoctorId
    WHERE p.PatientId = @PatientId;
END;

    Result:

    ┌───────────┬───────────────────┬────────┬─────┬───────────┬─────────────┬────────┬────────────┬────────────┬────────────────┐
│ PatientId │ FullName          │ DOB    │ Age │ StateName │ Insurance   │ Policy │ LastVisit  │ DoctorName │ Specialization │
├───────────┼───────────────────┼────────┼─────┼───────────┼─────────────┼────────┼────────────┼────────────┼────────────────┤
│ 1         │ Rajesh Kumar Reddy│ 1995   │ 30  │ Telangana │ Star Health │ P001   │ 2026-08-20 │ Dr. Anand  │ Cardiology     │
└───────────┴───────────────────┴────────┴─────┴───────────┴─────────────┴────────┴────────────┴────────────┴────────────────┘

    🎯 ఇది real EMR query pattern! మీ Falcon EMR project లో ఇలాంటివి వందల SPs ఉంటాయి.

    🎯 EMR లో Common JOIN Scenarios

    📋 Scenario 1: Patient Registration Dropdown Population

    Angular form load అయినప్పుడు State dropdown populate చేయాలి → no JOIN needed.

    SELECT *
FROM States;

    But Cities dropdown — state select చేసిన తర్వాత filter needed:

    CREATE PROCEDURE sp_GetCitiesByState
    @StateId INT
AS
BEGIN
    SELECT
        c.CityId,
        c.CityName
    FROM Cities c
    INNER JOIN States s
        ON c.StateId = s.StateId
    WHERE s.StateId = @StateId;
END;

    📋 Scenario 2: Patient Search List (Grid)

    CREATE PROCEDURE sp_SearchPatients
    @SearchText VARCHAR(100) = NULL
AS
BEGIN
    SELECT
        p.PatientId,
        p.PatientFName + ' ' + p.LastName AS FullName,
        p.DOB,
        s.StateName,
        c.CityName,
        ISNULL(i.CompanyName, 'Self-Pay') AS Insurance
    FROM Patients p
    INNER JOIN States s
        ON p.StateId = s.StateId
    LEFT JOIN Cities c
        ON p.CityId = c.CityId
    LEFT JOIN Insurances i
        ON p.InsuranceId = i.InsuranceId
    WHERE
        @SearchText IS NULL
        OR p.PatientFName LIKE '%' + @SearchText + '%'
        OR p.LastName LIKE '%' + @SearchText + '%';
END;

    💡 This is how AG Grid in your Angular EMR gets populated!

    📋 Scenario 3: Patient Vitals with Visit Info

    CREATE PROCEDURE sp_GetPatientVitals
    @PatientId INT
AS
BEGIN
    SELECT
        v.VitalId,
        v.BP,
        v.Pulse,
        v.Temperature,
        v.Weight,
        vt.VisitDate,
        vt.VisitType,
        d.DoctorName AS RecordedBy
    FROM Vitals v
    INNER JOIN Visits vt
        ON v.VisitId = vt.VisitId
    INNER JOIN Patients p
        ON vt.PatientId = p.PatientId
    LEFT JOIN Doctors d
        ON v.RecordedByDoctorId = d.DoctorId
    WHERE p.PatientId = @PatientId
    ORDER BY vt.VisitDate DESC;
END;

    📋 Scenario 4: Lab Orders with Results

    SELECT
    lo.OrderId,
    p.PatientFName + ' ' + p.LastName AS PatientName,
    lt.TestName,
    lr.ResultValue,
    lr.ResultDate,
    d.DoctorName AS OrderingDoctor
FROM LabOrders lo
INNER JOIN Patients p
    ON lo.PatientId = p.PatientId
INNER JOIN LabTests lt
    ON lo.TestId = lt.TestId
LEFT JOIN LabResults lr
    ON lo.OrderId = lr.OrderId
INNER JOIN Doctors d
    ON lo.OrderingDoctorId = d.DoctorId
WHERE lo.PatientId = @PatientId
ORDER BY lo.OrderDate DESC;

    🎨 Visual Cheat Sheet

    Table A (Patients)       Table B (Insurances)

    ┌──┐                     ┌──┐
    │  │                     │  │
    │AA│──── matching ─────│BB│
    │  │                     │  │
    └──┘                     └──┘

INNER JOIN → Only overlapping (AA ∩ BB)

LEFT JOIN  → Full A + overlapping

RIGHT JOIN → Full B + overlapping

FULL JOIN  → Everything from both (A ∪ B)

    🚀 Which JOIN to Use?

    Requirement JOIN to Use
    Patients with mandatory state info INNER JOIN
    All patients + their insurance (may or may not have) LEFT JOIN
    All states + patient count (even zero) RIGHT JOIN or LEFT JOIN
    Data reconciliation FULL OUTER JOIN
    Every patient × every doctor (rare) CROSS JOIN

    ⚠️ Common Mistakes to Avoid

    ❌ Mistake 1: Wrong JOIN → missing data

    SELECT
    p.*,
    i.CompanyName
FROM Patients p
INNER JOIN Insurances i
    ON p.InsuranceId = i.InsuranceId;

    Problem: Patients without insurance disappear.

    Fix: Optional right-side data అయితే LEFT JOIN use చేయాలి.

    SELECT
    p.*,
    i.CompanyName
FROM Patients p
LEFT JOIN Insurances i
    ON p.InsuranceId = i.InsuranceId;

    ❌ Mistake 2: Missing JOIN condition → Cartesian product

    -- WRONG
-- 100 patients × 50 states = 5000 rows!
SELECT *
FROM Patients p, States s;

    Fix: Always add an ON condition.

    SELECT *
FROM Patients p
INNER JOIN States s
    ON p.StateId = s.StateId;

    ❌ Mistake 3: NULL handling forgotten

    Wrong:

    SELECT
    p.Name,
    i.CompanyName
FROM Patients p
LEFT JOIN Insurances i
    ON p.InsuranceId = i.InsuranceId;

    Fix: Use ISNULL()

    SELECT
    p.Name,
    ISNULL(i.CompanyName, 'Self-Pay') AS Insurance
FROM Patients p
LEFT JOIN Insurances i
    ON p.InsuranceId = i.InsuranceId;

    Repository:

    public async Task<PatientDetailsDto?> GetPatientFullDetailsAsync(int patientId)
{
    var result = await _context.Set<PatientDetailsDto>()
        .FromSqlInterpolated(
            $"EXEC sp_GetPatientFullDetails @PatientId={patientId}"
        )
        .ToListAsync();

    return result.FirstOrDefault();
}

    📌 STEP 1: Create Database + Tables

    SSMS → New Query → paste → Execute (F5)

    -- =====================================================
-- Create Practice Database
-- =====================================================
IF NOT EXISTS (SELECT * FROM sys.databases WHERE name = 'JoinPracticeDB')
BEGIN
    CREATE DATABASE JoinPracticeDB;
END
GO

USE JoinPracticeDB;
GO

-- =====================================================
-- TABLE 1: Departments (Parent table)
-- =====================================================
IF OBJECT_ID('Projects', 'U') IS NOT NULL DROP TABLE Projects;
IF OBJECT_ID('Employees', 'U') IS NOT NULL DROP TABLE Employees;
IF OBJECT_ID('Departments', 'U') IS NOT NULL DROP TABLE Departments;
GO

CREATE TABLE Departments
(
    DeptId    INT PRIMARY KEY IDENTITY(1,1),
    DeptName  VARCHAR(50) NOT NULL,
    Location  VARCHAR(50)
);
GO

-- =====================================================
-- TABLE 2: Employees (Child of Departments)
-- DeptId is NULLable — some employees not assigned yet
-- =====================================================
CREATE TABLE Employees
(
    EmpId    INT PRIMARY KEY IDENTITY(1,1),
    EmpName  VARCHAR(50) NOT NULL,
    Salary   DECIMAL(10,2),
    DeptId   INT NULL,
    FOREIGN KEY (DeptId) REFERENCES Departments(DeptId)
);
GO

-- =====================================================
-- TABLE 3: Projects (Assigned to Employees)
-- EmpId is NULLable — some projects unassigned
-- =====================================================
CREATE TABLE Projects
(
    ProjectId    INT PRIMARY KEY IDENTITY(1,1),
    ProjectName  VARCHAR(100) NOT NULL,
    Budget       DECIMAL(12,2),
    EmpId        INT NULL,
    FOREIGN KEY (EmpId) REFERENCES Employees(EmpId)
);
GO

    🎯 Practice Queries — Q1 to Q10

    🔹 Q1: INNER JOIN — Employees with Department names

    SELECT
    e.EmpId,
    e.EmpName,
    e.Salary,
    d.DeptName,
    d.Location
FROM Employees e
INNER JOIN Departments d
    ON e.DeptId = d.DeptId;

    Expected: 6 rows.

    Ravi excluded because DeptId = NULL.

    Research department also excluded because it has no employees.

    🔹 Q2: LEFT JOIN — ALL employees + their department

    SELECT
    e.EmpName,
    e.Salary,
    ISNULL(d.DeptName, 'No Department') AS DeptName
FROM Employees e
LEFT JOIN Departments d
    ON e.DeptId = d.DeptId;

    Expected: 7 rows.

    Ravi is included with:

    No Department

    🔹 Q3: RIGHT JOIN — ALL departments + employees

    SELECT
    d.DeptName,
    d.Location,
    ISNULL(e.EmpName, 'No Employees') AS EmpName
FROM Employees e
RIGHT JOIN Departments d
    ON e.DeptId = d.DeptId;

    Expected: 7 rows.

    Research shows:

    No Employees

    🔹 Q4: FULL OUTER JOIN — Everyone from both tables

    SELECT
    ISNULL(e.EmpName, 'No Employee') AS EmpName,
    ISNULL(d.DeptName, 'No Dept') AS DeptName
FROM Employees e
FULL OUTER JOIN Departments d
    ON e.DeptId = d.DeptId;

    Expected: 8 rows.

    Includes:

    • Ravi — No Dept
    • Research — No Employee
    • 6 matched employee/department records

    🔹 Q5: 3-Table JOIN — Employees + Departments + Projects

    SELECT
    e.EmpName,
    d.DeptName,
    p.ProjectName,
    p.Budget
FROM Employees e
INNER JOIN Departments d
    ON e.DeptId = d.DeptId
INNER JOIN Projects p
    ON e.EmpId = p.EmpId;

    Expected: 5 rows.

    Rajesh appears twice because he has 2 projects.

    🔹 Q6: LEFT JOIN 3 Tables — All employees + projects

    SELECT
    e.EmpName,
    ISNULL(d.DeptName, 'No Dept') AS DeptName,
    ISNULL(p.ProjectName, 'No Project') AS ProjectName
FROM Employees e
LEFT JOIN Departments d
    ON e.DeptId = d.DeptId
LEFT JOIN Projects p
    ON e.EmpId = p.EmpId
ORDER BY e.EmpName;

    Priya, Divya and Ravi have:

    No Project

    🔹 Q7: Count Projects per Department

    SELECT
    d.DeptName,
    COUNT(p.ProjectId) AS TotalProjects,
    ISNULL(SUM(p.Budget), 0) AS TotalBudget
FROM Departments d
LEFT JOIN Employees e
    ON d.DeptId = e.DeptId
LEFT JOIN Projects p
    ON e.EmpId = p.EmpId
GROUP BY d.DeptName
ORDER BY TotalBudget DESC;

    e.EmpName,
    e.Salary,
    ISNULL(d.DeptName, 'No Dept') AS DeptName
FROM Employees e
LEFT JOIN Departments d
    ON e.DeptId = d.DeptId

    📝 Practice Exercise Answers

    ✅ Answer 1

    SELECT
    e.EmpName,
    ISNULL(d.DeptName, 'No Dept') AS DeptName,
    COUNT(p.ProjectId) AS ProjectCount
FROM Employees e
LEFT JOIN Departments d
    ON e.DeptId = d.DeptId
LEFT JOIN Projects p
    ON e.EmpId = p.EmpId
GROUP BY e.EmpName, d.DeptName
ORDER BY ProjectCount DESC;

    ✅ Answer 2

    SELECT TOP 1
    d.DeptName,
    SUM(e.Salary) AS TotalSalary
FROM Departments d
INNER JOIN Employees e
    ON d.DeptId = e.DeptId
GROUP BY d.DeptName
ORDER BY TotalSalary DESC;

    ✅ Answer 3

    SELECT
    p.ProjectName,
    p.Budget,
    e.EmpName,
    e.Salary,
    (e.Salary * 5) AS SalaryTimes5
FROM Projects p
INNER JOIN Employees e
    ON p.EmpId = e.EmpId
WHERE p.Budget > (e.Salary * 5);

    ✅ Answer 4

    SELECT DISTINCT
    d.DeptName
FROM Departments d
INNER JOIN Employees e
    ON d.DeptId = e.DeptId
LEFT JOIN Projects p
    ON e.EmpId = p.EmpId
WHERE p.ProjectId IS NULL
AND d.DeptId NOT IN
(
    SELECT DISTINCT e2.DeptId
    FROM Employees e2
    INNER JOIN Projects p2
        ON e2.EmpId = p2.EmpId
    WHERE e2.DeptId IS NOT NULL
);

    ✅ Answer 5

    SELECT TOP 3
    p.ProjectName,
    p.Budget,
    e.EmpName,
    d.DeptName
FROM Projects p
INNER JOIN Employees e
    ON p.EmpId = e.EmpId
INNER JOIN Departments d
    ON e.DeptId = d.DeptId
ORDER BY p.Budget DESC;

    🎯 JOIN Practice Tips

    Tip Explanation
    Aliases వాడండి Employees e, Departments d — readable code
    ON condition ఖచ్చితంగా ON e.DeptId = d.DeptId — miss చేస్తే Cartesian product
    ISNULL() వాడండి LEFT JOIN లో NULL వస్తే 'N/A' లాంటిది display చేయవచ్చు
    WHERE vs ON ON = join condition, WHERE = filter after join
    IS NULL trick Missing data find చేయడానికి LEFT JOIN + WHERE X IS NULL
